# Инструкции для ИИ-агентов (AI Rules)

Вы работаете в репозитории `nuExpert` — это жестко стандартизированный фреймворк на базе Nuxt 4, предназначенный для ИИ-агентов. Ваша цель — реализовывать бизнес-логику, строго следуя установленным архитектурным правилам. Если вы не уверены, перечитайте эти правила.

## Архитектура и Технологический Стек
* **Фреймворк:** Nuxt 4 (Vue 3 + Nitro).
* **Язык:** TypeScript повсеместно (strict mode). Использование `any` строго запрещено. Используйте `unknown` и безопасное сужение типов.
* **Бэкенд:** Только Nitro (папка `server/api/` и `server/routes/`). Никаких внешних бэкендов на Python/FastAPI или Node/Express.
* **База данных:** PostgreSQL через **Drizzle ORM** (драйвер `postgres-js`).
* **Валидация:** **Zod** для всех схем. Схемы должны быть единым источником истины (`shared/schemas/`). Выводите типы TS из схем Zod (`z.infer`).
* **Стилизация:** Tailwind CSS v4 (подключен через `@tailwindcss/vite`, а не через старый модуль Nuxt).

## Правила написания Frontend-кода (Vue 3 / Nuxt)
1. **Composition API:** Всегда используйте `<script setup lang="ts">`. Options API строго запрещен.
2. **Управление состоянием:** Используйте Pinia (`stores/`) для глобального состояния. Для локального — `ref` / `reactive` / `useState` (если нужен SSR).
3. **Разделение логики:** Выносите сложную бизнес-логику UI в Composables (`composables/`). Компоненты должны оставаться максимально "глупыми" (отвечать только за отображение и вызов методов).
4. **Роутинг:** Используйте файловый роутинг Nuxt (`pages/`). Не модифицируйте роутер вручную.

## Правила написания Backend-кода (Nitro)
1. **Изоляция слоев:** Серверный код (`server/`) не имеет права импортировать ничего из фронтенд-кода (`app/`). Это проверяется через `dependency-cruiser`. Разделяемые типы и схемы лежат в `shared/`.
2. **База данных:** 
   - Не держите соединения глобально открытыми.
   - Используйте ленивую инициализацию (`getDb()`).
   - Миграции генерируются через `drizzle-kit` и **обязательно коммитятся в репозиторий** в `server/database/migrations/`.
3. **Обработка ошибок:** 
   - Используйте `createError({ statusCode: ..., statusMessage: ... })`.
   - Не используйте пустые блоки `catch`.
   - Проверяйте типы ошибок: `if (typeof error === 'object' && error !== null && 'code' in error && (error as {code?: string}).code === '23505')`.

## Инфраструктура и DevOps
1. **CI/CD:** Любой ваш коммит будет проверен в GitHub Actions (Lint, Typecheck, Unit, E2E). Перед тем как сказать "Готово", убедитесь, что ваш код проходит проверки локально:
   - `npm run typecheck`
   - `npm run lint` / `npm run lint:deps`
   - `npm run test:coverage` (Покрытие должно быть ≥ 60/50%)
   - `npm run e2e`
2. **Docker:** Проект упакован в единый контейнер (Nuxt Nitro). `docker-compose.yml` поднимает приложение, БД и Redis.

Не нарушайте эти правила. Ваша задача — быть надежным исполнителем, который уважает границы фреймворка.
